# Loomline public memory contract 0.1

SDK version 0.1.0 is independent of FastAPI's application version. HTTP bearer authentication resolves tenant, agent and role on the server. Requests never choose a graph or authorship. Every scoped operation requires enabled task membership; invisible references return 404. Local token authentication is for self-hosted development, not a production identity provider.

Memory writes require operation_id, owned session_id, source_turn_id, class, assertion_type, status and content. Optional evidence_ids/entity_ids/supersedes_id reference authorized task data. Episodic permits episode/observation; semantic permits observation/hypothesis/decision; procedural permits procedure with bounded nonempty steps. Hypotheses and procedures start proposed; observations/episodes/decisions start active. Only coordinators publish decisions/procedures, approve procedures or create handoffs. Verifiers/coordinators challenge. Evidence is immutable; original support remains after dispute. Supersession requires a real replacement edge; retirement currently applies to procedures, not arbitrary records.

Commit receipts retain existing memory_id/reference/event_id/version fields. SDK receipt.id aliases the resource ID and receipt.outcome reports CREATED or REPLAYED from HTTP status without altering the server result. Full memory reads expose id/reference/task_id/class (SDK memory_class alias), assertion_type/status/content/created_by/source_turn_id/version/support/challenges/entities/steps and timestamps. session_id is optional when not present on the existing wire record; trace resolves it from the actual source turn. No fabricated provenance.

One operation ID is generated before any attempt. Same actor/task/kind/normalized payload replays original result (201 creation, 200 replay). Changed payload conflicts (409). Atomic modifying query couples memory/resource, Operation and its lifecycle event. Later challenges/status/handoff transitions create separate events with actor/reason/old/new versions. Source-turn convenience composition is TWO independent idempotent writes, never one transaction. An explicit original operation ID also deterministically derives its source-turn operation ID.

Turns are immutable visible user/assistant/tool records, allocated consecutively within owned sessions. System/developer instructions and hidden reasoning are not accepted. New resume creates a NEW authenticated session, retrieves bounded previous history/context/open work, and never impersonates the old agent or imports hidden context. Session context-manager exit retains server history and leaves the enclosing client available; client context-manager exit closes the HTTP pool.

Handoffs are open→accepted→done or open/accepted→cancelled with expected_version. Assignee accepts/completes; coordinator or assignee cancels. Procedures proposed→active require coordinator approval; proposed/active may retire. A successful commit does not promise synchronous notification: router is eventual/at least once, with frozen recipients and idempotent inbox pointers.

Errors preserve safe code/status: INVALID_INPUT (400), UNAUTHENTICATED (401), FORBIDDEN (403), NOT_FOUND (404), IDEMPOTENCY_CONFLICT / VERSION_CONFLICT / INVALID_TRANSITION (409), OVERLOADED (429), DATABASE_UNAVAILABLE (503), COMMIT_OUTCOME_UNKNOWN (504). SDK never includes headers, request payloads or raw provider errors in exception messages. Unknown writes retain operation ID for lookup/retry. Validation/permission/conflict errors are not retried. NIM retries and memory retry identities are separate.

Recall is bounded task/graph/substring filtering, not vector semantic search. Context bundles are per-query snapshots, not a multi-query transaction. Context budgets use approximate ceil(UTF-8 JSON bytes / 3), not a model tokenizer guarantee; retrieved text is untrusted and disputed/proposed claims remain labelled. Changes use atomic per-task event sequences, opaque tenant/task-bound versioned cursors and local explicit acknowledgment. Abandoned batches replay; consumers persist cursors/deduplicate event IDs. Future cursors conflict, wrong scope is invalid, incompatible cursor version expires. Current valid cursors have no automated expiry. Legacy unsequenced events remain available in history/trace, outside this feed. Deletion/retention workflows, private scopes and cross-task promotion are deferred.
